# Decisions

Decisions made while building the SDKs, beyond what `specs/marketsdk-sdks/requirements.md` in `marketsdk-specs` already settles. Each says what was decided and why, so nobody reopens it by accident.

| | Decision | Why |
| --- | --- | --- |
| D1 | Fern's organization name is `MarketSDK`, not `marketsdk`. | Fern derives names it has no setting for (README titles, PHP exception classes) from the organization name. `marketsdk` gave `Marketsdk`. `MarketSDK` gives `MarketSdk` in the two PHP exception names and the README titles, which is the closest Fern's casing rules allow. Every name that has a setting is set explicitly. |
| D2 | The TypeScript types namespace is `MarketSDKApi`. | A class and a namespace cannot both be exported as `MarketSDK` from the package index; Fern dropped the client export when asked. The class keeps the brand name, since it is what every customer types. |
| D3 | `searchListings` is pinned by an overlay, with its request type's name. | Fern strips an operationId prefix that matches the resource name, so it would have been `client.search.listings()`. The rule is that operationId is the method name. The overlay adds Fern's method-name extension to that one operation, and the request-name extension so the request type stays `SearchListingsRequest`. The description is untouched. |
| D4 | Fern's `changelog.md` is removed from every repository. | It carries the generation date, which would make two runs on the same inputs differ. Release notes live in the registry and GitHub release metadata. |
| D5 | Fern's `.fern/` metadata folder is removed. | It records the generator configuration, which `GENERATED` and this repository already do. |
| D6 | The `X-Fern-SDK-*` request headers stay. | They go only to api.marketsdk.com, alongside `User-Agent`, and let the backend's request log tell SDK traffic from hand-written clients. They send nothing to Fern. |
| D7 | Every run packages, in Fern's `--package-mode docker`. | Fern writes a complete, buildable project to the local file system only when it packages; without that flag the TypeScript, Python, and Java outputs are source-only trees with no build files. Packaging also builds each library in the language's official image, which is the compile check the requirements ask for, and needs no toolchain on the machine. The artifacts are discarded. |
| D8 | `pnpm-lock.yaml` stays in the TypeScript repository. | It is identical across runs, so it does not break determinism, and a committed lockfile makes the repository build the same way everywhere. |
| D9 | Python's `pyproject.toml` has an empty `description` and `authors`. | Fern's Python generator fills those only from a PyPI output block, which local generation does not use, and the `pyproject_toml` extra block cannot redefine a table the generator already writes. PyPI shows the README, so nothing is lost on the package page. |
| D10 | The C# and PHP clients are `MarketSDKClient`. | Their namespace is `MarketSDK`. C# warns when a type shares its namespace's name, and PHP reads badly. Required by `requirements.md` section 4. |
| D11 | TypeScript, Go, and C# take a small request object for a path id, `getSeller({ id })`; Python, Java, and PHP take the id directly. | That is each Fern generator's convention, and the generators' inline-path-parameter settings changed nothing when tried. Consistency across languages is not worth fighting the generators for. |
| D12 | The Java `build.gradle` gets two scripted corrections after generation: the scm block's repository URL, and the POM's `name`. | Fern fills the scm URL only when it publishes to GitHub itself, and writes the publisher's name as the POM's name. Maven Central requires both to be right. This is the only change made to generated output, it is deterministic, and the script fails if the generator's text changes so it is never applied blindly. |
| D13 | The smoke tests live in this repository, under `smoke/`, not in the SDK repositories. | An SDK repository holds generated output only. The tests reference each library by local path and run against a local backend, which is this repository's concern. |
| D14 | The backend used for smoke tests accepts `host.docker.internal` as an API host. | The Java, C#, and PHP tests run in Docker and reach the host that way. It is a local setting, `MARKETSDK_API_HOSTS=127.0.0.1,host.docker.internal`, and never a production one. |
